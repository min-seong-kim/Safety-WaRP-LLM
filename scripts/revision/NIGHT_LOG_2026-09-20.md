인데 `maxsplit=1` 이라 **절대경로에서는 basename 이 아니라 `NHNHOME/.../이름` 이 나온다.**

## 05:4x — 결과 추출기가 downstream 을 조용히 날리던 버그 (수정 완료)

대기 시간에 `gen_exp_results_rows.py` 를 미리 시험하다 발견했다. 이미 측정된 값이
표에서 `—` 로 나왔다:

```
llama2_7b-chat-...-asft_gsm8k_..._tgtonly   AVG=0.0624  down=—   (실제 측정값 0.2252)
```

**원인.** 추출기는 "그 모델이 들어 있는 **가장 최근 통합 CSV** 행"을 택했다. 그런데
`RESUME=true LMEVAL_RESUME=1` 로 다시 돌리면 lm-eval 이 이미 끝난 task 를 건너뛰므로,
그 실행의 통합 CSV 에는 **ASR 만 채워지고 downstream 열은 빈칸**이 된다. 이 빈칸이
이전에 제대로 측정된 값을 덮어썼다. ASR 빈칸에 대한 방어는 이미 있었지만
(`_AVG` 가 비면 건너뜀) downstream 에는 없었다.

**수정.** `load_rows()` 를 **행 단위 → 열 단위 병합**으로 바꿨다. 각 열마다 "값이 들어 있는
가장 최근 CSV" 를 따로 고르고, 빈칸은 절대 덮어쓰지 않는다.

```
수정 후:  asft_gsm8k_..._tgtonly  AVG=0.0624  down=0.2252   ✅
          lisa_gsm8k_..._tgtonly  AVG=0.0548  down=0.2411   ✅
```

**영향 범위.** 기존 `RESULTS.md` 는 무사하다 — 추가 실험 5/6 표의 downstream 은 전부 채워져
있고, `—` 로 남은 칸은 Δ 열(기준행이 없거나 ARC 기준모델이 깨진 경우)로 의도된 공백이다.
이 버그는 **앞으로 생성할 표**(C1/C2 평가 결과)를 조용히 망가뜨릴 뻔했다.

⚠️ 이 수정은 "열마다 출처 CSV 가 다를 수 있다" 는 뜻이기도 하다. 모델을 재학습했는데 옛
downstream 값이 남아 있으면 그대로 끌려올 수 있으니, 재학습한 셀은 측정 시각을 확인할 것
(`gen_results_md.py` 가 쓰는 허브 `lastModified` 대조와 같은 취지).

**교훈:** 단계가 rc=0 으로 끝났다고 일을 했다는 뜻이 아니다. 평가 단계는 **대상 개수**를
